Приложение для автоматической синхронизации рейтингов (от 1 до 5 звёзд) и лайков между аудиофайлами и сервером Navidrome (Subsonic/OpenSonic API).



## Возможности
- Режимы синхронизации:
  - двусторонняя (объединение)
  - односторонняя: Файлы → Navidrome / Navidrome → Файлы.
 
- Поддерживаемые форматы: FLAC, OGG, Opus, MP3, AIFF, WAV (ID3v2.4), APE, WavPack (APEv2), M4A (AAC/ALAC), WMA. Остальные форматы пропускаются без сообщений в логе.

- Совместимость с лайками в формате MusicBee (тег LOVE RATING).

- Гибкое расписание: запуск по интервалу, ежедневно в точное время или вручную из Home Assistant (кнопка / автоматизация).
 
- Режим Dry Run: предварительный просмотр планируемых изменений в логах без физической записи в аудиофайлы/сервер.

- Атомарная запись (опционально): режим Copy-Save-Replace защищает аудиофайлы от порчи при одновременной записи несколькими пользователями/процессами, если медиатека доступна по сети (SMB/NFS). Атомарная запись отключена по умолчанию для предотвращения износа SSD.

- Защита данных от сбоев питания: изменения записываются сразу на диск в обход системного буфера, минимизируя случаи потери данных при внезапном отключении электричества.

- Независимая обработка рейтингов и лайков: можно включить синхронизацию только лайков или только рейтингов. Если включены оба параметра, то обновляются только изменившиеся данные, например, при изменении лайка тег рейтинга в файле не перезаписывается.

- Устойчивость к сбоям: сетевые ошибки и недоступность сервера не приводят к рестартам приложения — синхронизация продолжит запускаться по расписанию.



### Основные сценарии использования 
- Разовый перенос оценок:
Navidrome не умеет импортировать оценки из файлов в свою базу данных и, наоборот, не записывает оценки из своей базы обратно в теги файлов. Если вам нужно однократно перенести оценки с одной стороны на другую, используйте одностороннюю синхронизацию.

- Регулярная синхронизация:
Вы получаете доступ к медиатеке удаленно через Subsonic-клиенты (например, Symfonium на телефоне), в этом случае оценки сохраняются только в базе сервера. При этом дома вы используете локальный плеер (например, MusicBee), который может записывать и читать оценки, работая с тегами аудиофайлов. В такой ситуации приложение будет синхронизировать сервер и файлы, чтобы обеспечить "бесшовное" использование — независимо от того, где именно вы оценили трек.



### Как это работает
В тегах аудиофайлов не фиксируется дата присвоения или изменения оценок. При этом Navidrome фиксирует в своей базе дату/время, но Subsonic API не поддерживает передачу этих данных для рейтингов. По API можно получить только время установки лайка, но данные о снятии лайка недоступны. Из-за этих ограничений приложение ведёт собственную базу данных и сохраняет снимок последнего известного состояния каждого трека с обеих сторон, чтобы корректно разрешать конфликты данных насколько это возможно. Цикл в режиме двусторонней синхронизации:

- Оценки на сервере и в файлах сравниваются со снимком состояний из базы данных аддона — так определяется, какая сторона изменилась с прошлой синхронизации. Для быстродействия теги файлов не перечитываются с диска, если время изменения файла (mtime) совпадает со значением в базе аддона с прошлой синхронизации, то оценка берётся из базы (кеша).

- Если оценка изменилась только на одной стороне — она копируется на другую.

- Если оценки изменились с обеих сторон между двумя запусками синхронизации (конфликт) — побеждает приоритетный источник, выбранный в настройках приложения (Server wins / File wins). Поэтому, чем чаще интервал запуска синхронизации, тем точнее определяется изменившаяся сторона.

- Снимок состояний обновляется в базе данных аддона и становится новой «точкой отсчёта».



## Требования
- Установка Home Assistant с Supervisor (протестировано на HAOS).
- Аддоны [Navidrome](https://github.com/alexbelgium/hassio-addons/tree/master/navidrome) и Rating Sync должны быть установлены в одной инсталляции Home Assistant — оба приложения должны работать с одинаковыми путями к аудиофайлам.
- Музыкальная библиотека должна быть доступна из Home Assistant одним из способов:
    - Внутренний диск HAOS (папка /media).
    - Внешний диск, примонтированный к HAOS — [инструкция](https://gist.github.com/microraptor/be170ea642abeb937fc030175ae89c0c)
    - Сетевой диск (SMB) — [инструкция как подключить в Home Assistant](https://www.home-assistant.io/common-tasks/os/#network-storage)
- При изменениии оценки в тегах файла, должна обновляться и `mtime` — дата изменения файла.

Приложение протестировано только с Navidrome v0.63.2. Теоретически синхронизация может работать и с другими Subsonic серверами, так как используется стандартное API (работа с библиотекой сервера — py-opensonic, работа с тегами файлов — mutagen).

## Настройка и запуск приложения
- Укажите логин/пароль того пользователя, чьи оценки должны синхронизироваться. В Navidrome рейтинги и лайки хранятся для каждого пользователя отдельно.

- Выберите режим синхронизации, расписание, и включите режим Dry Run (настоятельно рекомендуется для первого раза).

- Запустите приложение, выполнив первое подключение к Navidrome, чтобы создать виртуальный плеер "Rating Sync Agent [Python]". Поскольку Navidrome по умолчанию отдает относительные пути, приложение не сможет сопоставить треки сервера с файлами на диске и сообщит об ошибке.

- В веб-интерфейсе Navidrome авторизуйтесь под тем же пользователем, которого указали в настройках приложения. Перейдите в Preferences → Players → Откройте настройки клиента "Rating Sync Agent [Python]" → Включите опцию «Report Real Path» → Save.

- Перезапустите приложение и откройте лог — вкладка «Журнал», проверьте, корректны ли планируемые изменения (тестовые записи в режиме Dry Run в логе будут помечены префиксом [DRY-RUN]).

- Если всё верно — отключите Dry Run и перезапустите приложение, чтобы запустить синхронизацию в режиме записи данных.



## ⚠️ Настройка локального плеера и редактирование тегов
Приложение синхронизирует только те оценки, которые физически записаны в теги аудиофайлов. Многие аудиоплееры по умолчанию хранят оценки только в своей внутренней базе — в этом случае приложению будет нечего синхронизировать. Убедитесь, что ваш плеер поддерживает запись оценок в теги аудиофайлов и эта функция включена.

Включение опции записи рейтинга/лайка в теги на примере MusicBee:
- Откройте раздел настроек тегов: Preferences → Tags (1)
- Включите опцию «Сохранять рейтинги в треки»
- В опции «Сохранять теги MP3 как» желательно выбрать ID3v2.4

### Редактор тегов
Если вы меняете оценки с помощью редактора тегов, то убедитесь, что в его опциях отключено сохранение исходной даты изменения файла. Так как если дата изменения файла не будет меняться, то приложение не прочитает из него новую оценку.

## ⚠️ Важные особенности
- **Абсолютные пути:** треки на сервере сопоставляются с файлами строго по их полному пути. Если в Navidrome не включена опция «Report Real Path», синхронизация завершится с ошибкой, о чем будет указано в логе. 

- **Автоматический старт:** процесс синхронизации запускается сразу при старте приложения. Не запускайте аддон, пока не убедитесь, что все опции настроены корректно.

- **Первый запуск в двухстороннем режиме при пустой базе:** если рейтинг трека в файле и на сервере различается (оба НЕ нулевые), конфликт не решается автоматически — расхождение просто фиксируется в логе. Разрешить его можно ручным изменением оценки на одной из сторон, либо временно запустив одностороннюю синхронизацию с затиранием данных на принимающей стороне.

- **Первый запуск в одностороннем режиме синхронизации:** все оценки на принимающей стороне затираются оценками источника.

- **Односторонняя синхронизация — не зеркало:** новые изменения из источника переносятся на принимающую сторону. Но если после этого вручную изменить оценку на принимающей стороне, она не будет принудительно перезаписана старым значением из источника. Перезапишется только если оценка будет обновлена в источнике.

- **Обрабатываются только известные треки:** файлы, которых ещё нет в базе Navidrome (не отсканированы сервером), игнорируются приложением.

- **Перемещение или переименование файлов:** приложение находит треки по пути, который отдаёт сервер. Если вы переместили или переименовали файлы, то пересканируйте библиотеку в Navidrome (при этом уже имеющиеся данные об оценках в файлах и на сервере не потеряются).


### Ограничения
- **Рейтинги и лайки однопользовательские:** поддерживается 1 пользователь и 1 музыкальная библиотека в Navidrome. В тегах файлов хранится только одна оценка.

- **Дробные звёзды:**
    - Navidrome понимает только целые числа, поэтому при отправке рейтинга на сервер, например, 3,5 звезды — значение всегда округляется вверх до целой звезды.
    - В файлах дробная оценка сохраняется до тех пор, пока не будет перезаписана новым значением с сервера.
    - При сравнении допускается разница в 0,5 звезды. Расхождение в пределах ползвезды (например, 3,5 в файле и 4 на сервере) считается совпадением, и синхронизация не выполняется.



### Какие теги читаются и записываются
| Формат | Рейтинг | Лайк |
| :--- | :--- | :--- |
| MP3, AIFF, WAV | POPM (ID3v2.4) | TXXX:LOVE RATING |
| FLAC, OGG, Opus | RATING | LOVE RATING |
| APE, WavPack | RATING (APEv2) | LOVE RATING |
| M4A | RATE | LOVERATING |
| WMA | WM/SharedUserRating | musicbee/LOVE RATING |

Если MP3-файл содержит несколько рейтинговых фреймов POPM от разных плееров (MusicBee, WMP и др.), то при чтении приоритет у фреймов MusicBee, затем no@email. 
При записи обновляются все существующие фреймы, чтобы все плееры увидели актуальную оценку.



### Снятие/обнуление оценки
- Рейтинг (0 звёзд): 
  - FLAC/OGG/Opus/APE/WavPack/M4A/WMA тег рейтинга **удаляется** из файла.
  - MP3/AIFF/WAV фреймы POPM не удаляются, а обнуляются, при этом счетчик прослушиваний не затрагивается и сохраняет накопленную статистику.

- Лайк: тег `LOVE RATING` не удаляется — в него записывается значение «0», чтобы MusicBee корректно обновил данные в своей внутренней базе.



### Особенности одностороннего режима синхронизации
В одностороннем режиме данные передаются строго в одном направлении — от источника к приемнику, при этом:

- Принимающая сторона не становится зеркалом, и измененные на ней оценки не затираются.  
ПРИМЕР: в режиме синхронизации «Navidrome → Файлы» вы изменили оценку в файле с 3 на 5. При следующей синхронизации аддон запомнит это изменение и не откатит новую оценку старым значением с сервера (из источника). Трек будет считаться условно синхронизированным. Однако, если позже вы измените оценку на сервере (источнике данных), то при следующей синхронизации оценка в файле будет перезаписана значением с сервера в соответствии с режимом «Navidrome → Файлы».

- Переключение режима синхронизации с одностороннего на двухсторонний.  
ПРИМЕР: в режиме синхронизации «Navidrome → Файлы» вы изменили оценку в файле с 3 на 5. Новая оценка в файле сохранится и трек будет считаться условно синхронизированным. Если вы переключитесь в двусторонний режим синхронизации, то более новая оценка «5» из файла автоматически отправится на сервер как самая свежая. Аналогичное правило применится к лайкам.

- Одновременное изменение обеих сторон: если с момента прошлой синхронизации вы поменяли оценку и в файле, и на сервере, то при следующей синхронизации, оценка на принимающей стороне будет перезаписана оценкой из источника.



### Защита от параллельного запуска
Команда запуска, поступившая во время выполнения цикла синхронизации, игнорируется. Это исключает наложение циклов и повторную обработку треков при двойном нажатии кнопки или одновременном срабатывании автоматизаций в Home Assistant.



### База данных приложения
Снимки состояния треков хранятся в базе данных приложения. Перезапуск или обновление приложения не затрагивают базу.  
При этом сброс базы может быть необходим, если вы кардинально меняете конфигурацию (пользователя, путь к библиотеке и др.).  
Чтобы удалить базу данных, удалите приложение с включенной опцией «Также удалить данные приложения» и установите его заново.



### Обработка ошибок
| Ситуация | Поведение |
| :--- | :--- |
| Ошибка обработки отдельного трека (нет прав, повреждённый файл) | Ошибка логируется, обработка остальных файлов продолжается |
| Неудачная запись данных на диск | Состояние трека в базе аддона не обновляется — попытка записи повторится в следующем цикле синхронизации|
| Subsonic сервер недоступен | Цикл синхронизации пропускается, повтор выполняется по расписанию (если настроено) |
